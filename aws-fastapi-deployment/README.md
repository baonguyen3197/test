# FastAPI on real AWS

This is separate from the LocalStack lab. **Real AWS resources cost money**, even
when the API is idle. Review the cost section and the Terraform plan before
applying. No resources are created by `terraform init` or `terraform plan`.

The instructions below use Ubuntu in WSL. Run all commands in the same WSL
terminal. They assume the repository is at `/mnt/d/trustify`.

## What this creates

```text
Internet -- HTTPS --> ALB (two public AZ subnets)
                        |
             +----------+----------+
             |                     |
       ECS task, AZ 1        ECS task, AZ 2
             +----------+----------+
                        |
           RDS PostgreSQL Multi-AZ
             primary + standby
```

The two ECS services each use one private subnet. RDS uses two private subnets
for its primary and standby. Two NAT gateways let ECS pull images and reach
AWS services. The app uses the RDS instance endpoint.

The ALB terminates HTTPS with an existing ACM certificate, redirects HTTP to
HTTPS, and forwards to ECS on port 8000. Database credentials are generated by
RDS and stored in Secrets Manager. CloudWatch receives the application logs.
This project does not create a domain, DNS record, or certificate.

## Before starting

You need:

- An AWS account with permission to deploy VPC, EC2 networking, RDS, ECR, ECS,
  ELB, IAM, CloudWatch Logs, S3 and Secrets Manager resources, including
  service-linked roles and `iam:PassRole`. Use a temporary deployment role or
  IAM Identity Center; do not use root credentials.
- A domain you control and an **issued ACM certificate in the selected region**
  covering that domain. Have its ARN ready; do not paste credentials into chat.
- Two available AZs, and an RDS PostgreSQL version and instance class
  supporting Multi-AZ DB instances in your account and region.
- WSL tools: AWS CLI v2, Docker with WSL integration, Python 3 and Terraform
  1.10 or later. Check with:

  ```bash
  aws --version
  docker version
  python3 --version
  terraform version
  ```

  If Terraform is missing, install the Linux version using the
  [official instructions](https://developer.hashicorp.com/terraform/install).

## 1. Sign in to AWS

For IAM Identity Center, configure and sign in to a new profile:

```bash
aws configure
export AWS_PROFILE=fastapi-aws
export AWS_REGION=ap-southeast-1
export AWS_DEFAULT_REGION=ap-southeast-1
export AWS_PAGER=""
unset AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY AWS_SESSION_TOKEN AWS_ENDPOINT_URL
export AWS_IGNORE_CONFIGURED_ENDPOINT_URLS=true
aws sts get-caller-identity
```

## 2. Choose AZs, engine version, and certificate

```bash
aws ec2 describe-availability-zones \
  --filters Name=state,Values=available Name=zone-type,Values=availability-zone \
  --query 'AvailabilityZones[].ZoneName' --output table

aws rds describe-orderable-db-instance-options \
  --engine postgres --db-instance-class db.m6gd.large \
  --query 'OrderableDBInstanceOptions[?SupportsStorageEncryption==`true`].[EngineVersion,StorageType]' \
  --output table

aws acm list-certificates --certificate-statuses ISSUED \
  --query 'CertificateSummaryList[].[DomainName,CertificateArn]' --output table
```

Choose **two** available AZs, a PostgreSQL version with `io1` support, and
the ARN of the issued certificate for your domain. If `db.m6gd.large` is not
available, choose another supported Multi-AZ DB instance class and run the RDS
query again. Verify account quotas and capacity before applying. The example
values in the file are placeholders, not guaranteed availability.

## 3. Create a state bucket

Before this step, complete step 4 below to load the environment. The provided
environment file derives a globally distinct state bucket name from the active
AWS account. Then create it before running `terraform init`:

```bash
set -e
test -n "$STATE_BUCKET"
aws s3api head-bucket --bucket "$STATE_BUCKET" 2>/dev/null || {
  aws s3api create-bucket --bucket "$STATE_BUCKET" \
    --region "$AWS_REGION" \
    --create-bucket-configuration "LocationConstraint=$AWS_REGION"
}
aws s3api put-bucket-versioning --bucket "$STATE_BUCKET" \
  --versioning-configuration Status=Enabled
aws s3api put-public-access-block --bucket "$STATE_BUCKET" \
  --public-access-block-configuration \
  BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
aws s3api get-bucket-versioning --bucket "$STATE_BUCKET"
set +e
```

Stop if the placeholder check or any command fails. The `head-bucket` command
reuses an existing bucket; creation only runs when it cannot be found. The
final command should report `Enabled`. S3 encrypts new objects by default;
Terraform also requests encryption and uses an S3 lock file. Restrict access
to the bucket and protect state and backups: state can contain sensitive
information.

## 4. Set Terraform inputs

```bash
cd /mnt/d/trustify/aws-fastapi-deployment/terraform
cp environments/dev/backend.hcl.example environments/dev/backend.hcl
cp environments/dev/environment.env.example environments/dev/environment.env
nano environments/dev/environment.env
source environments/dev/environment.env
```

Set the supported DB engine version and instance class, certificate domain,
and state bucket. The region and Terraform variables are exported by
`environment.env`. Verify them before continuing:

```bash
printf 'region=%s\nbucket=%s\nprofile=%s\n' \
  "$AWS_REGION" "$STATE_BUCKET" "$AWS_PROFILE"
```

If any value is empty, do not continue. Do not add AWS credentials or a DB
password: authenticate with AWS SSO/temporary credentials, and RDS generates
the database password.

## 5. Initialize, plan, and create the infrastructure

```bash
terraform init -reconfigure -input=false \
  -backend-config=environments/dev/backend.hcl \
  -backend-config="bucket=$STATE_BUCKET" \
  -backend-config="region=$AWS_REGION"
terraform fmt -check -recursive
terraform validate
terraform plan -out=tfplan
```

Check the plan and the account carefully. The next command **creates
billable resources**, including one RDS Multi-AZ DB instance (primary and
standby) and two NAT
gateways, even with zero ECS tasks:

```bash
terraform apply tfplan
```

Type `yes` only after reviewing the plan. RDS creation can take a long time.
The ECS services have zero tasks until the image is pushed.

## 6. Build and push the app

```bash
REPO="$(terraform output -raw ecr_repository_url)"
REGISTRY="${REPO%%/*}"
aws ecr get-login-password --region "$AWS_REGION" |
  docker login --username AWS --password-stdin "$REGISTRY"
docker buildx build --platform linux/amd64 --load -t "$REPO:latest" \
  /mnt/d/trustify/localstack-fastapi-deployment/compose
docker push "$REPO:latest"
aws ecr describe-images --repository-name fastapi-aws \
  --query 'imageDetails[].imageTags' --output json
```

The last command assumes the default project name `fastapi-aws`. If you change
`name`, use that name as the ECR repository name too.

## 7. Start both app tasks

```bash
export TF_VAR_tasks_per_az=1
terraform plan -out=tfplan
terraform apply tfplan
```

Review the plan before applying. The example requests one task per application
AZ. Check the services and target group:

```bash
CLUSTER="$(terraform output -raw ecs_cluster_name)"
mapfile -t SERVICES < <(terraform output -json ecs_service_names |
  python3 -c 'import json,sys; print(*json.load(sys.stdin), sep="\n")')
aws ecs describe-services --cluster "$CLUSTER" --services "${SERVICES[@]}" \
  --query 'services[].{Name:serviceName,Desired:desiredCount,Running:runningCount}' --output table

TARGET_GROUP="$(terraform output -raw target_group_arn)"
aws elbv2 describe-target-health --target-group-arn "$TARGET_GROUP" \
  --query 'TargetHealthDescriptions[].{IP:Target.Id,State:TargetHealth.State}' --output table
```

Wait until both services report one running task and **two distinct targets
are healthy**. To see the AZ of each task:

```bash
for service in "${SERVICES[@]}"; do
  echo "$service"
  tasks="$(aws ecs list-tasks --cluster "$CLUSTER" --service-name "$service" \
    --desired-status RUNNING --query 'taskArns' --output text)"
  if [ -n "$tasks" ] && [ "$tasks" != "None" ]; then
    aws ecs describe-tasks --cluster "$CLUSTER" --tasks $tasks \
      --query 'tasks[].[taskArn,availabilityZone,lastStatus]' --output table
  else
    echo "No running task"
  fi
done
```

If tasks fail, inspect ECS service events and the CloudWatch log group from
`terraform output -raw log_group_name`.

## 8. Configure DNS and test HTTPS

```bash
terraform output -raw alb_dns_name
```

At your DNS provider, point the domain covered by your certificate to the ALB.
For a subdomain use a CNAME; for a zone apex use a DNS-provider-supported alias
to the ALB. Wait for DNS propagation. Replace the example below with your
actual domain:

```bash
export API_DOMAIN="fastapi-app.com"
curl --fail-with-body "https://$API_DOMAIN/health"
curl --fail-with-body "https://$API_DOMAIN/db-check"
```

Expected: `{"status":"ok"}` and `{"db_status":"ok","result":1}`. Open
`https://YOUR-DOMAIN/docs` for the API docs. The raw ALB DNS name will not
match a certificate issued for your domain.

To check that requests reach **both** apps, send marked requests and count their
CloudWatch streams (logs can take time to appear):

```bash
marker="$(python3 -c 'import uuid; print(uuid.uuid4().hex)')"
for i in $(seq 1 30); do curl -fsS -o /dev/null "https://$API_DOMAIN/health?test=$marker"; done
sleep 30
aws logs filter-log-events --log-group-name "$(terraform output -raw log_group_name)" \
  --filter-pattern "\"$marker\"" --query 'events[].logStreamName' --output text |
  tr '\t' '\n' | sort | uniq -c
```

Two different task log streams with requests and two healthy targets are
evidence of routing to both tasks. Recheck task AZs using step 7.

## 9. Inspect the RDS instance and optionally test failover

```bash
DB="$(terraform output -raw rds_instance_identifier)"
aws rds describe-db-instances --db-instance-identifier "$DB" \
  --query 'DBInstances[0].{Identifier:DBInstanceIdentifier,PrimaryAZ:AvailabilityZone,StandbyAZ:SecondaryAvailabilityZone,MultiAZ:MultiAZ,Status:DBInstanceStatus,Endpoint:Endpoint.Address}' --output table
```

Check that the instance has a primary and standby in two AZs. To
deliberately test failover, first ensure the database is disposable or backed
up. The following command **interrupts database connections** and may cause
requests to fail during promotion:

```bash
aws rds reboot-db-instance --db-instance-identifier "$DB" --force-failover
aws rds wait db-instance-available --db-instance-identifier "$DB"
aws rds describe-db-instances --db-instance-identifier "$DB" \
  --query 'DBInstances[0].{PrimaryAZ:AvailabilityZone,StandbyAZ:SecondaryAvailabilityZone,Status:DBInstanceStatus}' --output table
curl --fail-with-body "https://$API_DOMAIN/db-check"
```

Compare the primary AZ before and after. This demo makes a new DB connection for
each request; it does not demonstrate retries or zero-downtime failover.

## 10. Clean up

Destroying the instance deletes its data after AWS creates the final snapshot.
Confirm backups and review every plan. Deletion protection is enabled by
default; first disable it intentionally:

```bash
export TF_VAR_db_deletion_protection=false
terraform apply
```

Empty the project ECR repository using the AWS console first; Terraform will
not delete a repository containing images. Then:

```bash
terraform destroy
```

The final RDS snapshot, the manually created state bucket and its object
versions remain and may continue to cost money. Delete them separately only
when you are sure they are no longer needed. If a snapshot named
`fastapi-aws-final` already exists, resolve that name conflict before
destroying. DNS records and the existing ACM certificate are not managed by
this project.

## Security and cost notes

- The API is publicly accessible and has no authentication; this is a demo,
  not a production-ready public service.
- The app uses the RDS **master user**. Use a separate least-privilege
  application database user for production.
- RDS generates the password and Secrets Manager stores it. ECS injects it
  at task startup, not on every request. This demo disables automatic rotation
  to avoid silently breaking running tasks; arrange a rotation procedure and
  redeploy both ECS services after rotating the secret. Do not use this as a
  production credential-management pattern.
- HTTPS protects client-to-ALB traffic; ALB-to-task traffic is HTTP inside the
  VPC. Database storage is encrypted. Treat Terraform state as sensitive.
- Cost drivers include one RDS Multi-AZ deployment (primary and standby),
  provisioned storage and IOPS,
  two NAT gateways and data processing, ALB hours/LCUs, two Fargate tasks,
  CloudWatch logs, Secrets Manager, ECR, S3, snapshots, and data transfer.
  Charges begin at the first apply, including before tasks start.
- Prices vary by class, region, duration and usage. Use the
  [AWS Pricing Calculator](https://calculator.aws/) with `ap-southeast-1`,
  one `db.m6gd.large` RDS PostgreSQL Multi-AZ DB instance, 100 GiB
  allocated storage and 1,000 provisioned IOPS, two NAT gateways,
  one ALB and two 0.25 vCPU/0.5 GiB Fargate tasks. Check the calculator's
  Multi-AZ storage and IOPS billing model rather than assuming a free tier.
  No live price estimate has been verified here.
